# Snapcompose

Веб-конструктор иллюстраций для тестового «Очень» / Снэпбилд.

Собирает композиции **только** из готовой SVG-библиотеки (10 объектов × L/S × main/background).  
Новые объекты не генерируются. Экспорт — редактируемый SVG.

## Запуск

```bash
cd web
npm install
npm run dev
```

Открой URL из терминала (обычно http://localhost:5173).

## Что умеет

1. **Сценарий 1** — метафора/заголовок → подбор объектов из каталога → автораскладка  
2. **Сценарий 2** — имена компонентов (`книга, лампа, наушники`) → компоновка  
3. Ручное добавление из библиотеки, drag, масштаб, поворот, слои  
4. Main ↔ Background, Size L/S, 3 цветовые схемы с перекраской  
5. Форматы: квадрат / горизонталь / вертикаль  
6. Скачать итоговый SVG

## Архитектура

### Слои

| Слой | Где | Зачем |
|------|-----|--------|
| Каталог | `src/data/catalog.ts` | id, имена, теги для метафор |
| Палитры | `src/data/palettes.ts` | 3 схемы + карта перекраски от scheme-1 |
| SVG loader | `src/lib/svg.ts` | загрузка, кэш, recolor, export |
| Layout | `src/lib/layout.ts` | эвристики assembled / offset / title |
| Metaphor | `src/lib/metaphor.ts` | LLM → план; fallback локальный; только id каталога |
| LLM proxy | `vite.llmPlugin.ts` | `POST /api/llm/plan` (OpenAI-compatible) |
| Ассеты | `public/library/**` | исходные векторы (копия из `../assets`) |
| Плоскость фона | `public/planes/{square\|horizontal\|vertical}/` | **отдельная** раскладка штрихов/овалов под каждый формат кадра |

Сценарий 1: `planFromMetaphor` вызывает LLM через proxy, затем `sanitizePlan` отбрасывает любые id вне каталога. Если ключа нет или API упал — локальная эвристика.

### Хранение, извлечение и переиспользование SVG

**Хранение.** Библиотека — неизменяемые векторные ассеты версии приложения (10 объектов × L/S × main/background). Файлы лежат в `public/library/{L|S}/{main|background}/*.svg`; логическая модель — в `catalog.ts` (id → путь к файлу, имена, теги). Исходники в git (`../assets`) версионируются вместе с кодом.

**Извлечение.** UI/движок запрашивает объект по `id` + `size` + `role`. `loadSvg` делает `fetch` URL и кладёт markup в in-memory `Map`-кэш. `extractInnerSvg` достаёт `viewBox`, размеры и внутренний markup без обёртки `<svg>`.

**Переиспользование.** Один и тот же файл может попасть на холст много раз (дубликаты — отдельные scene-items с общей ссылкой на ассет). Перекраска (`recolorSvgMarkup`) и трансформы (x/y/scale/rotation) применяются к **копии** markup / к состоянию сцены, исходный SVG в `public/library` не мутируется. Экспорт собирает итоговый редактируемый SVG из плоскости фона + размещённых элементов.

```
catalog.ts ──► URL ассета ──► loadSvg (кэш) ──► extractInnerSvg
                                      │
                                      ▼
                         scene items (копии + transform)
                                      │
                                      ▼
                         recolor (копия) → SVG export
```

### Почему не БД и не CDN в MVP

Библиотека фиксирована ТЗ («заранее подготовленная»), объекты не генерируются и не загружаются пользователем. Для такого набора правильнее **asset pipeline** (файлы + каталог), а не БД:

- ассеты версионируются с релизом, демо поднимается без отдельного бэкенда;
- CDN — это доставка, не хранилище; на локальном/простом хостинге статика уже отдаётся как static files;
- БД оправдана, когда есть user upload, ACL, тысячи объектов или обновление библиотеки без редеплоя.

**Масштабирование без смены ядра:** object storage (S3) + CDN для файлов, каталог/метаданные в БД, upload API — при этом Composition Engine, recolor и exporter остаются теми же.

## LLM (сценарий 1)

1. Скопируй `.env.example` → `.env`
2. Укажи `LLM_API_KEY` (или вставь ключ в панели «LLM для метафор»)
3. По умолчанию: `https://api.openai.com/v1` + `gpt-4o-mini`
4. Подойдут OpenRouter / Groq и другие OpenAI-compatible endpoint’ы — поменяй Base URL и Model  
   (для демо удобен Groq: `https://api.groq.com/openai/v1`, модель вроде `openai/gpt-oss-20b`)

Ключ из UI хранится в `sessionStorage` и уходит только на same-origin proxy (не в клиентский бандл напрямую к провайдеру).

## AI-инструменты при разработке

| Инструмент | Роль |
|------------|------|
| Cursor (агент) | Сборка веб-MVP, нормализация SVG из Figma-экспорта, архитектура каталога/палитр |
| OpenAI-compatible LLM API (Groq / OpenAI / др.) | Сценарий 1: анализ метафоры → план объектов только из каталога |
| Локальный heuristic fallback | Работа без ключа/при ошибке API |

AI в продукте **не рисует** новые path: только выбирает id из `CATALOG` и параметры раскладки; `sanitizePlan` отбрасывает всё вне библиотеки.
